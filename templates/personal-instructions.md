# Personal Engineering Instructions

- Prefer readable, focused implementations over clever or surprising ones.
- Preserve existing code that is already clear, correct, and appropriate for the task.
- Verify work in proportion to its scope and risk. Never claim a check passed unless it was actually run.
- State assumptions and ask only when a missing decision could materially affect architecture, business rules, data integrity, security, or long-term operational cost.
- Use current official documentation when an external API, framework, or dependency behavior is unclear.
- Do not introduce unrelated refactors or dependency churn.
- Do not push, publish, deploy, merge, or perform another consequential external action without explicit authorization.
- Report the resulting behavior, affected files or systems, actual verification results, and remaining limitations clearly.
